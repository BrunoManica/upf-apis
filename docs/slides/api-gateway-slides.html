Objetivo da aula

Entender por que o cliente acessa vários serviços por uma única entrada.

Vamos acompanhar o roteamento entre usuários e produtos, entender filtros e reconhecer onde entram autenticação, rate limiting e cache.

solucao / porta unicacom gateway

Com API Gateway

O cliente conhece apenas a porta 8080.

/api/users→users-service:8081/users
/api/products→products-service:8082/products

Os serviços continuam separados. O gateway apenas esconde os endereços internos e encaminha cada chamada.

Recebe

arquitetura / tres aplicacoesseparado

Três aplicações independentes

users-service

Expõe dados de usuários em /users.

products-service

Expõe dados de produtos em /products.

gateway-service

Expõe /api/users e /api/products.

Cada aplicação tem processo, porta e responsabilidade próprios. Isso é importante: o gateway não é uma classe dentro dos outros serviços.

filtros / antes e depoisfilter chain

Filtros atuam na passagem

Reescrever URL

Ajusta o caminho antes de enviar.

Adicionar header

Inclui contexto na requisição ou resposta.

Registrar logs

Ajuda a acompanhar entrada e destino.

Bloquear chamada

Interrompe quando uma regra transversal falha.

Filtros cuidam da comunicação. Eles não devem conter cálculo de desconto, estoque ou regra de cadastro.

evolucao / controles transversaisroadmap

Controles transversais no gateway

Autenticação

Valida o token e pode responder 401 antes do serviço.

Rate limiting

Bloqueia excesso de chamadas com 429.

Cache

Reutiliza respostas públicas e pouco variáveis por um período curto.

Observabilidade

Mede latência, erros e destinos acessados.

Não faça cache de dados privados, saldo, pagamento ou respostas dependentes da identidade. Rate limiting também não substitui autenticação e autorização.

limites / o que nao colocarboundary

Gateway não é serviço de negócio

  • Não busca usuário no banco: isso pertence ao users-service.
  • Não calcula preço: isso pertence ao products-service ou orders-service.
  • Não valida estoque: o domínio responsável deve fazer isso.
  • Não substitui autorização interna: cada serviço ainda protege suas regras críticas.

debug / erros comunsreview

Erros comuns

  • Usar a mesma porta em duas aplicações.
  • Testar o gateway antes de confirmar que os serviços respondem diretamente.
  • Configurar o caminho público corretamente, mas esquecer de ajustar o prefixo esperado pelo serviço.
  • Apontar o destino para uma porta ou host incorreto.
  • Adicionar autenticação, cache e limites antes de entender e validar o roteamento básico.
  • Usar cache para dados privados, sensíveis ou muito variáveis.
  • Colocar regra de negócio em filtros do gateway.

resumo / leitura finalcomplete

Resumo

Porta única

O cliente acessa o sistema pelo gateway na porta 8080.

Rotas e filtros

Condições escolhem o destino; filtros ajustam e controlam a chamada.

Responsabilidade

O gateway controla a entrada; os serviços cuidam do negócio.

O gateway pode centralizar autenticação, rate limiting e cache seguro. Seu valor não é juntar os serviços, mas organizar como o mundo externo chega até eles.
